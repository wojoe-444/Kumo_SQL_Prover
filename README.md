# Kumo SQL Prover

An equivalence prover for BigQuery SQL. Given two queries, it says whether they return the same rows on every database (**proven equivalent**), shows a database on which they differ (**not equivalent**, with a counterexample), says they are equal only when stated facts hold (**equivalent under conditions**), or declines (**unknown**). Unknown is always preferred to wrong: every row of the scoreboard below says how many answers were wrong, and that number is meant to stay 0.

This is the prover of [KumoSQL](https://github.com/wojoe-444/KumoSQL), split out as step 8 of its [roadmap](https://github.com/wojoe-444/KumoSQL/blob/master/docs/roadmap.md). KumoSQL depends on a pinned release of this package, so a change here reaches KumoSQL only as a version bump. Nothing in this package imports KumoSQL.

## Install

```sh
pip install "kumo-sql-prover @ git+https://github.com/wojoe-444/Kumo_SQL_Prover@cf1f74a2a913cfe621031797dc60fe5448ba80de"
pip install "kumo-sql-prover[smt,execution] @ git+https://github.com/wojoe-444/Kumo_SQL_Prover@cf1f74a2a913cfe621031797dc60fe5448ba80de"   # Z3 and DuckDB
```

That commit is release v0.1.0. The `v0.1.0` tag could not be created from the session that merged the first pull request; once the maintainer tags the commit, `@v0.1.0` names the same thing.

`sqlglot==30.21.0` is the only supported version. Python 3.11 or newer.

## Use

```python
from kumo_sql_prover import prove_equivalent, prove_equivalent_smt

# The structural prover: both queries normalize to the same tree (layout, case and spacing do not matter).
result = prove_equivalent("SELECT id FROM t WHERE a = 1", "select id\nfrom t where a=1")
print(result.status, result.proven)        # PROVEN_EQUIVALENT True

# The SMT prover (needs the [smt] extra) proves a pair the structural one only calls "not proven":
result = prove_equivalent_smt(
    "SELECT id FROM (SELECT id, a FROM t WHERE a = 1) AS s WHERE id > 0",
    "WITH s AS (SELECT id, a FROM t WHERE id > 0) SELECT id FROM s WHERE a = 1",
)
print(result.status)                       # SmtStatus.PROVEN_EQUIVALENT
```

`NOT_PROVEN` and `UNKNOWN` never mean the queries differ: only a counterexample does.

The provers are separate entry points, from the cheapest to the most expensive:

| Module | What it does |
| --- | --- |
| `kumo_sql_prover.equivalence` | Structural proof: normalize both queries and compare, with an independent checker for each step |
| `kumo_sql_prover.algebraic_equivalence` | Multiplicity algebra (the idea behind SQLSolver): unions, aggregates over unions, regrouping |
| `kumo_sql_prover.smt_equivalence` | Z3 over a symbolic model of the query, with BigQuery's number and error rules |
| `kumo_sql_prover.bounded_equivalence` | Every database up to N rows per table, counterexamples replayed on DuckDB |
| `kumo_sql_prover.result_equivalence` | Same results on generated datasets, a refutation or supporting evidence only |
| `kumo_sql_prover.sqlsolver_backend` | The algebraic prover, then the real SQLSolver jar when one is installed |
| `kumo_sql_prover.tie_determinism`, `tie_witness` | Windows, `LIMIT`s and aggregates whose result depends on how tied rows are ordered |

```sh
python -m kumo_sql_prover smt left.sql right.sql --schema schema.json      # or: kumo-prove-smt ...
python -m kumo_sql_prover sqlsolver left.sql right.sql --schema schema.json
```

See [docs/provers.md](docs/provers.md) for the full reference and [docs_simple/provers.md](docs_simple/provers.md) for the plain-language version. [docs/README.md](docs/README.md) indexes every page.

## Tests

```sh
pip install -e ".[dev]" sqlglotc==30.21.0     # sqlglotc is the compiled build CI uses, optional
python -m pytest -n auto -m "not eval" --quick   # the pull-request gate (skips the slow tier)
python -m pytest -n auto -m "not eval"           # everything but the benchmark floors, slow tier included
python -m pytest -n auto -m eval                 # the benchmark floors (slow)
```

The gate runs on every pull request; the slow tier is the tests `tests/order.json` lists (about two seconds or more each, measured over many runs in KumoSQL). The benchmark floors and the slow tier run on a schedule ([benchmarks.yml](.github/workflows/benchmarks.yml)) and open an issue when one drops; they report, they do not gate a change.
